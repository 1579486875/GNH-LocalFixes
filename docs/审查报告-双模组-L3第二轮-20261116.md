## 4. 本轮发现的模板问题（给模板留的）

- [ ] **§3.2.4「先怀疑脚本」已经不够用了，要再加一句「先查配置文件」**。
  本轮判定「诊断工具默认关着却在跑」时，顺着源码查了 `TryInstall` → `IsFixEnabled` →
  `IsOn` → `IsDefaultOff`，**每一环都对、行为不对**，差点判成开关机制失效。
  真相是配置文件里就是 `true`（`Config/Mod_<模组名>_<设置类>.xml`，
  **不是** `Config/ModSettings/<packageId>.xml`）。
  → 建议：判「某开关该不该生效」时，**必须读配置文件**，不能只看默认值逻辑。
  `IsDefaultOff` 管的是「**没写过这一项时**用什么值」，写过之后它整段不参与。
- [ ] **§1.1 的「版本号三处一致」应补一句：`<Version>` 写在 csproj 里但工程设了
  `GenerateAssemblyInfo=false` 时不生效**。本仓库反过来了（GNH 的 csproj 注释明确写「本行真正生效」），
  但同一个用户的两个仓库用了两套惯例，靠人记必错。→ 建议：一律改成脚本核 DLL 反射值，不看源码。
- [ ] **§B.9「日志膨胀 ≠ 红字刷屏」可以补一条**：`Responding = False` 也可能只是别人的重活
  （本轮实测 YART 建 571 万字符搜索索引 53 秒 + Combat Extended 初始化 871 个定义），
  判活仍要看 CPU 与日志增量。
