# 第三轮复审：5 次「先怀疑脚本」的实证（2026-11-17）

模板 §3.2.4 说「审计脚本报『不通过』时，先怀疑脚本」。这一轮又验证了 5 次 ——
**全部是脚本口径问题，不是模组缺陷**。

| # | 脚本 | 误报 | 真实原因 |
|---:|---|---|---|
| 1 | `check-definjected-keys.py` | `Wait` / `Wait_Combat` / `Wait_MaintainPosture` 三个原版 JobDef 报「悬空键」 | **只扫了 `Mods` + `workshop`，漏了原版与 DLC 的 `Data\`**。补上后：109,150 个 defName，0 悬空 |
| 2 | 同上 | 「独立版 1.5 / 1.6 的 `1.5/Defs` 与 `1.6/Defs` 里 0 个 defName」 | **独立版的 `Defs` 在 `Common/`**（`1.5/`、`1.6/` 只有 `Assemblies` + `Source`）。按 `LoadFolders` 的声明查才对：`Common` 有 429 xml / 5,350 defName |
| 3 | `check-placeholders.py` | 4 条 `NMM.Log.*.Unaware` 报「英文有占位符、中文没有」 | **英文用 `{SELF_objective}self` 拼反身代词**，中文没有这种构词法，少一个是对的 —— 该进白名单，不是缺陷 |
| 4 | 「1.6 可达性检查」 | `SR_HuoShu_TattooIcon` 报「1.6 与 1.7 都不存在」 | **我手抄目标列表时打错了**。补丁里写的是 `SR_HuoShu_Tattoo_Slot1`（带下划线），它在 workshop `3643594275/1.6/Defs` 里正常存在 |
| 5 | 同上 | `FWQ_FamilyCheckIn` 报「1.6 缺」 | **不是缺陷**：`betaforher.hotwiferjw` 那个模组**根本没装进 1.6 副本的 `Mods\`**（只装在 1.7 主安装）。补丁里的 `PatchOperationFindMod` 会让它整块静默跳过 |

## 修正后的真实结论

```
DefInjected 键：24,946 个 · 悬空 0 · 重复 0
占位符对账：471 键 · ❌ 0 · ⚠ 0
XML 补丁的 31 个 defName 目标 + 5 个 Name 模板：
  1.6 下缺 1 个（FWQ_FamilyCheckIn，因为那个模组没装 —— 正常空转）
  其余全部可达
1.7 正文 Keyed 的 19 种占位符（89,187 次）：全部在 NMM 的 DLL 里有对应字面量
```

## 一句话

**五次「报错」里有四次是我自己的判据不全、一次是数据本来就该那样。**
如果照着第一版结论去「修」，会把 5 处正确的东西改坏。
