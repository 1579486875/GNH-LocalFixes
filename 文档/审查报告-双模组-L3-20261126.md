## 1. 本轮查出并修掉的 5 个问题

### ① 【70】新增：背景故事创建器一打开就崩（新功能）

「背景故事创建器」（BackstoryConstructor，工坊 2907131508）编辑器窗口
一打开就抛 `NullReferenceException`，「禁用特性 / 绑定特性」两栏画不出来。

**反编译定位到作者三处缺陷叠加**：

```csharp
// ① 构造函数是空的 → 两个 List 字段初值 null
public BackstoryTemplate() { }

// ② ExposeData 的 Scribe_Collections.Look 第 4 参是 params ctorArgs、不是默认值
Scribe_Collections.Look<string>(ref forcedTraits, "forcedTraits",
                                LookMode.Value, Array.Empty<object>());
// 配置里没有该键 → 字段保持 null

// ③ 绘制时不判空
if (!first.Contains(traitInfo) && !second.Contains(traitInfo))   // ← 崩在这里
```

**实测**：配置里 1 个模板（`BackstoryTemplate_1`）当时两个字段都不存在。

**修法（双保险）**：
- `BackstoryTemplate.ExposeData` 的 **Postfix**：读盘后把 null 补成空列表（治本）
- `Window_BackstoryConstructor.DrawBackstoryTraits` 的 **Prefix**：绘制前再兜一层
- 全程反射，模组不在场静默跳过；空列表与「没有禁用/绑定特性」语义一致，**不改任何既有数据**

**实机确认**：
```

编辑器里的「禁用特性 / 绑定特性」不会再因为空列表整栏画不出来。
```

## 3. 本轮一个重要的认知纠正

**上一轮我曾报「14 个文件用了 21 处 `PatchOperationSequence`，内部操作全部带 success」。**

本轮用 XML 解析复核：**实际 Sequence 是 0 处**。那 21 次全都出现在**注释里** ——
作者在 `ConfigErrorCleanup.xml` 第 35 行写明：

> 全部平铺成独立 Operation，不套 PatchOperationSequence。
> Sequence 的语义是「任一子操作失败即中止后续」，而本补丁每个 xpath
> 都带 not(...) 前置条件：作者自己补了字段、或模组没装时，xpath 会……

**所以「grep 到的次数」不等于「实际用了」。** 以后查这类结构必须走 XML 解析。
