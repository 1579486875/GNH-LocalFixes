
**关键点**：

- `VK_ERROR_DEVICE_LOST` = **Vulkan 图形设备丢失**（驱动重置 / GPU 挂了 / 窗口被销毁）
- 栈顶在 `PresentFrame`（**提交画面**），不是游戏逻辑
- 最后一步是 `PlatformBase.Exit` → `OnMainSurfaceDestroyed` → `ShutdownGraphics` ——
  **是退出路径上的设备丢失**，不是某段模组代码抛的异常

加载 1,176 个模组的纹理时压力峰值容易把设备顶掉。

## 为什么判断与模组无关

| 依据 | 说明 |
|---|---|
| 异常类型 | `VK_ERROR_DEVICE_LOST` 是图形 API 层错误，不是托管异常 |
| 栈的位置 | 全在 `Waylith.*` 渲染管线里，没有一帧是模组代码 |
| 我们的日志 | 崩溃前 `Patch class installed` = 11、`GNH LocalFixes` 的 ERROR = **0** |
| 可复现性 | 同一天 14:12 那次同样配置跑到主菜单（53 分钟）；16:46 这次 48 分钟崩 —— **不是确定性失败** |
| 与【70】的关系 | 【70】的绘制补丁**只在窗口绘制时**执行；崩溃发生在**加载阶段**，早于任何窗口绘制 |

## 如果反复崩，可以做的（按代价从低到高）

1. **窗口化 + 降分辨率** —— 改 `Prefs.xml` 的 `<fullscreen>False</fullscreen>`，
   降低纹理/后处理压力（**改前必须完全退出游戏**，否则会被写盘覆盖）
2. **指定用独显跑** —— Windows 设置 → 系统 → 显示 → 图形 →
   添加 `RimWorldWin64.exe` → 选「高性能（NVIDIA）」
   或 NVIDIA 控制面板 → 管理 3D 设置 → 程序设置
3. **更新/回滚显卡驱动** —— 尤其 AMD 核显驱动（32.0.11036.4）
4. **关掉虚拟显示器**（GameViewer Virtual Display Adapter）再跑
