## 二、已排除的四个假设

### ❌ 假设 1：`first` / `second` 参数是 null

**排查**：反编译 `DrawMainRect`，它有 `if (backstoryTemplate != null)` 守卫，
两个 wrapper 传的是同一对列表，只是顺序相反：

```csharp
DrawBackstoryTraits(..., backstoryTemplate.disallowedTraits, backstoryTemplate.forcedTraits);  // 第 1 次
DrawBackstoryTraits(..., backstoryTemplate.forcedTraits,     backstoryTemplate.disallowedTraits);  // 第 2 次
```

而循环里是：

```csharp
if (!first.Contains(traitInfo) && !second.Contains(traitInfo))
```

**`&&` 短路**解释了「为什么只有第二次崩」：

| 调用 | `first` | 行为 |
|---|---|---|
| 第 1 次 | `disallowedTraits` | 若非 null → 不崩 → `&&` 短路 → `second` 根本不求值 |
| 第 2 次 | `forcedTraits` | 若为 **null** → `first.Contains` 崩 |

**结论**：这个假设**方向是对的**（真凶是 `forcedTraits` 为 null），
但**具体原因不是「配置缺键」** —— 见假设 2。

### ❌ 假设 2：配置文件缺 `<forcedTraits>` / `<disallowedTraits>` 键

**排查**：反编译 `Verse.Scribe_Collections.Look`（1.7.5014）：

```csharp
if (Scribe.EnterNode(label))
{
    ...
    else   // 不是 IsNull="True"
    {
        case LookMode.Value:
            list = new List<T>(curXmlParent.ChildNodes.Count);   // ← 空元素 → new List(0)
            ...
    }
}
if (Scribe.mode == LoadSaveMode.LoadingVars)
{
    ...
    list = null;    // ← 只有 EnterNode 失败（节点不存在）才置 null
}
```

**判定规则**：

| 配置里的形态 | 读盘后 |
|---|---|
| `<forcedTraits />`（空元素） | `new List<string>(0)` —— **非 null** |
| `<forcedTraits IsNull="True" />` | `null` |
| **没有这个节点** | `null` |

**实测当前配置**（`Mod_2907131508_BackstoryConstructorMod.xml`，63,698 B，13:51）：

```
模板数: 2
BackstoryTemplate_1   forcedTraits=存在(子节点0)  disallowedTraits=存在(子节点0)
BackstoryTemplate_2   forcedTraits=存在(子节点0)  disallowedTraits=存在(子节点0)
```

**两个模板都有空节点，0 个子节点** → 按上表，读盘后应是**两个空 List**，**不是 null**。

**结论**：**「配置缺键」不成立**。

### ❌ 假设 3：`BackstoryTemplate` 没实现 `IExposable`，导致反序列化失败

**排查**：`find_base_types` 显示 `bases=[] interfaces=[]`，一度以为类型没实现接口。

但反编译 `Verse.ScribeExtractor.SaveableFromNode`：

```csharp
IExposable exposable = CreateInstance(type, ctorArgs);
...
exposable.ExposeData();      // 强类型调用
```

若 `BackstoryTemplate` 真没实现 `IExposable`，这里会 NRE 并被 catch →
`Log.Error("SaveableFromNode exception: ...")`。

**实测日志**：

```
grep -c "SaveableFromNode exception" → 0
grep "BackstoryConstructor" 且含 error/exception → 0
```

**结论**：反序列化**成功**，`IExposable` 是实现着的
（`find_base_types` 对跨程序集接口解析不全，不能作为判据）。

### ❌ 假设 4：特性标签里带方括号，导致 `degree` 解析失败 → `Find` 返回 null

**排查**：作者那段代码：

```csharp
string text = traitInfo.Split('~')[0].Trim();
int.TryParse(traitInfo.Split('[').Last().Split(']')[0], ref degree);
TraitDef val3 = TraitDef.Named(text);
TraitDegreeData val4 = val3.degreeDatas.Find(x => x.degree == degree);
val2.Add(new DebugMenuOption(val4.LabelCap + ...));      // ← NRE 在这里
```

目录项格式是 `"{defName} ~ ({label}) [{degree}]"`。若 label 自带方括号，
`Split('[').Last()` 取到的就不是 degree 那一节。

**离线复现**（脚本 `_scratch/r60/复现特性解析.py`，扫全库 TraitDef 后按同样写法拼串再解析）：

```
找到 37 个 TraitDef（含 degreeDatas）
作者会生成的目录项: 77 条
能正常解析: 77 条（100.0%）
会返回 null → NRE: 0 条
```

**结论**：**一条都不会解析失败** → 「标签带方括号」不成立。
（清洗逻辑作为防御保留，但它不是本问题的解药。）

### ❌ 假设 5（部分）：`Harmony` 的 `ref` 参数能改掉传入的引用

**这条是被实机日志直接推翻的**，不是假设而是一个**已确认的错误**：

上一版用：

```csharp
private static void DrawTraitsPrefix(ref List<string> first, ref List<string> second)
```

实机日志：

```
- PREFIX gnh.cn.cys.localfixes: ...DrawBackstoryTraits
         <- DrawTraitsPrefix(List`1& first, ...)
System.NullReferenceException at DrawBackstoryTraits(...)
```

**PREFIX 挂上了、签名也对、方法体拿到的仍然是 null。**

**原因**：Harmony 的 `ref` 参数**只在原方法参数本身是 `ref`/`out` 时才写回**。
作者的 `DrawBackstoryTraits(..., List<string> first, List<string> second)` 是
普通值传递，前缀改的只是形参副本。

**正确做法**：直接改 `Window_BackstoryConstructor.backstoryTemplate`
（**private static** 字段）所指对象上的两个 `List` 字段 —— 这样参数传进来时就已经非 null。

### 最终修法（生效的那一版）

**核心是「直接改 `backstoryTemplate` 上的字段」**：

```csharp
// Prefix 无参；顺 private static 的 backstoryTemplate 改字段
object template = windowTemplateField.GetValue(null);
if (forcedTraitsField.GetValue(template) == null)
    forcedTraitsField.SetValue(template, new List<string>());
if (disallowedTraitsField.GetValue(template) == null)
    disallowedTraitsField.SetValue(template, new List<string>());
```

**为什么不能用 `ref` 参数**：Harmony 的 `ref` 只在原方法参数本身是
`ref`/`out` 时才写回；作者的 `DrawBackstoryTraits(..., List<string> first, List<string> second)`
是普通值传递，前缀改的只是形参副本 —— 这一条被实机日志直接证实
（PREFIX 挂上了但方法体仍拿到 null）。

### 观察到的遗留现象（不影响本问题）

点 `+` 弹出的 `Verse.FloatMenu` 里，选项文字显示成
`类型为…` + 多行 `System.String` 之类的调试串。
**这是作者 `DebugMenuOption` 的 label 拼装问题**（`val4.LabelCap + " (" + val3.modContentPack.Name + ")"`），
与我们的补丁无关 —— 我们只动了列表的**成员**，没动 label 的**拼法**。
菜单能弹出、能点，本问题（点不开）已解决。
