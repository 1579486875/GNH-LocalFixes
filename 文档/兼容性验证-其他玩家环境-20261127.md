# 其他玩家环境下的兼容性验证

**日期：2026-11-27**
**对象**：**多模组红字修复补丁**<br>`gnh.cn.cys.localfixes` v1.4.65

---

## 0. 为什么要专门验这个

本补丁修的是 **39 个第三方模组**的缺陷。本机环境是 1,176 模组、全 DLC、中文本地化，
**但其他玩家可能完全不是这个配置**：

- 只装了一半目标模组，或一个都没装
- 装的是**旧版**目标模组（方法签名不同）
- 装的是**新版**目标模组（作者已自行修好）
- 纯原版 + 只装我们这一个补丁
- 缺 DLC、英文环境、繁中环境

**这些情况下补丁必须「安静让路」，而不是报错、更不能崩游戏。**

## 1. 静态审计：40 个安装点的让路能力

逐个检查 `源码/*.cs` 里每个 `Install()`：

| 判据 | 结果 |
|---|---|
| 用反射拿目标（`AccessTools.TypeByName` / `AccessTools.Method`） | **40 / 40** |
| 拿到后判空、拿不到就 `return` | **40 / 40** |
| 跳过时打日志说明原因 | **40 / 40** |
| `Mod` 构造函数有一次性守卫（防重入叠加） | 见 §1.1 |

### 1.1 关于守卫

| 安装点 | 守卫 | 说明 |
|---|---|---|
| `LocalFixesMod` 构造函数 | `private static bool constructorRan` | 2026-11-27 按模板 §4 补上 |
| `BackstoryConstructorTraitsFix.Install()` | `if (installed) return` | 已有 |

> 反编译 `Verse.LoadedModManager` 可复验：`CreateModClasses()` 自带
> `if (!runningModClasses.ContainsKey(type))` 去重，**成功返回的模组不会被重复构造**；
> 唯一重入路径是「构造函数抛异常」。两道守卫覆盖了这条路径。

### 1.2 让路的三种形态（模板 §3.1）

| 形态 | 实例 |
|---|---|
| **类型存在性** | `AccessTools.TypeByName("BackstoryConstructor.Window_BackstoryConstructor")` 为 null → 跳过 |
| **目标方法存在性** | `AccessTools.Method(type, "DrawBackstoryTraits")` 为 null → 跳过 |
| **前置模组在场性** | 39 个目标登记 `requiresModById`，设置界面会标「目标模组未启用」 |

## 3. 旧版目标模组的兼容性

**情形**：玩家装着旧版目标模组，方法签名与新版本不同。

**补丁的行为**：`AccessTools.Method(type, "方法名")` 在「同名方法有重载、无法唯一确定」时
返回 null（这个行为在 `SteamWorkshopHookFix.cs` 的注释里记着），于是判空 → 跳过 → 打日志。

**结论**：最坏情况是**该修复不生效**，不会是「崩游戏」。
玩家会在日志和设置界面看到「目标模组未启用 / 已改版」，知道该修什么。

## 5. 一个必须说明的限制

**本补丁没有实现「目标模组在场但版本过旧、方法签名恰好兼容」这一档的检测。**

即：如果某个目标模组的旧版**恰好保留了同名同签名的方法，但内部语义变了**，
本补丁仍然会挂上去 —— 这种情况只能靠 §1.4 的「反编译目标当前版本」在维护时发现，
运行时无法自动识别。

**这是三判据（类型/方法/前置模组）的共同盲区**，模板 §3.1 已经明确指出：

> 这三种判据的共同盲区：它们只能检测「目标**消失**」，检测不了
> 「目标**还在**、但缺陷已经被作者修好了」。

**缓解方式**：每个补丁都有独立的设置开关，玩家遇到问题可以单独关掉某一项；
某个目标模组更新后，我们这边按 §1.4 复核再决定是否让它退役。

---

## 6. 结论

**其他玩家环境的兼容性是站得住的**：

- **最坏情况实测通过** —— 只装 Core + Harmony + 本补丁时，**零错误、19 条让路、13 秒到主菜单**
- **40 个安装点全部具备「反射 + 判空 + 跳过日志」**
- **两道幂等守卫**覆盖了「构造函数抛异常导致重入」这条唯一路径
- 缺 DLC / 英文 / 繁中 三项未实测，但代码路径都走反射 + 判空，最坏结果是「该修复不生效」
