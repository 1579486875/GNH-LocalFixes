## 4. 四类开关的判断机制（静态验证）

闸门 `工具/verify-toggles.py` 的对账结果：

```
声明 78 项 / 接线 78 项（TryInstall 43 + 补丁类 10 + SCC 3 + XML 22）
声明了但没接线 : 无
接线了但没声明 : 无
重复 Id        : 无
结论：全部对上
```

逐类确认判断点：

| 类型 | 数量 | 判断位置 | 确认 |
|---|---|---|---|
| **TryInstall 型** | 43 | `LocalFixesMod.TryInstall` 开头 `if (!IsFixEnabled(toggleId))` | ✅ |
| **PatchClass 型** | 10 | `LocalFixesMod` 里统一 `if (toggleId != null && !IsFixEnabled(toggleId))` | ✅ |
| **SCC 型** | 3 | 各自 `[StaticConstructorOnStartup]` 静态构造里查 | ✅ |
| **XmlPatch 型** | 22 | `xmlPatchFile:` 命名参数登记 → `XmlPatchGate.BuildMap()` 建表 → `Patch_PatchOperation_Apply` 的 Prefix 拦截 | ✅ |

### 4b. XmlPatch 型的双向核对（这一项最容易出错）

```python
FixToggles 里登记的 xmlPatchFile: 22 个
Patches/*.xml 实际:              22 个
有文件但没登记开关: 0 个
登记了但没文件    : 0 个
✅ 22 个一一对应
```

`XmlPatchGate.BuildMap()` 的实现（反编译确认）：

```csharp
FixToggles.Entry[] all = FixToggles.All;
for (int i = 0; i < all.Length; i++) {
    FixToggles.Entry e = all[i];
    if (e == null || e.XmlPatchFile.NullOrEmpty()) continue;
    map[e.XmlPatchFile] = e.Id;
}
```

建表失败时会打 `XmlPatchGate: 建表失败，本次不拦截任何 XML 补丁` —— **不会静默失效**。

## 5. 动态验证：开关真的能开能关（对照实验）

静态只能证明「有接线」，不能证明「关掉真的不生效」。所以做了**同一开关的 True/False 对照**。

**对象**：【1】`assemblyGetTypesFallback`（`AssemblyGetTypesFallbackFix`）

**环境**：最小环境（`ludeon.rimworld` + `brrainz.harmony` + 本补丁），加载约 13 秒

### 5.1 开关 = False

日志：

```
INFO [GNH LocalFixes] Skipped, turned off in mod settings:
                       AssemblyGetTypesFallbackFix [assemblyGetTypesFallback].
```

**没有** `Installed the Assembly.GetTypes() safety net` 这条。

### 5.2 开关 = True（对照组）

日志：

```
INFO [GNH LocalFixes] Installed the Assembly.GetTypes() safety net
                       on 1 implementation(s) (System.Reflection.Assembly.GetTypes)
```

**同一条开关，True 时装上、False 时跳过。**

### 5.3 顺带观察到的第二个

设置文件里 `deepProfilerQuiet` 本来就是 `False`，启动日志里同样出现：

```
INFO [GNH LocalFixes] Skipped, turned off in mod settings: DeepProfilerQuietFix [deepProfilerQuiet].
```

说明「设置文件里的值 → 实际行为」这条链路是通的。

## 6. 查出的真缺陷：README 那句是错的

### 6.1 原文

```
（**78 个开关覆盖 71 条编号里的 70 条** —— 唯一没有独立开关的是【1】：
  它是给 ElToro 补一个任务类型，类型必须编进 dll 才能被解析，运行时关不掉，删掉 `Assemblies…`）
```

### 6.2 实际

- **【1】的开关是 `assemblyGetTypesFallback`**，源码注释还写着
  「本组排在最前的是【1】：它不修某一条具体症状，而是「整批补丁能不能装上」的地基」
- **它的内容早已不是 ElToro 任务类型**，而是「`Assembly.GetTypes` 兜底」
  —— 说明**编号被重新分配过**，那句话是旧版遗留
- 而且它**能正常关掉**（第 5 节的对照实验就是拿它做的）

### 6.3 已修正

```
（**71 条编号全部有独立开关**，一对一：编号 1–71 ↔ 71 个开关 id，
  另加 7 个不带编号的附加开关 —— 5 个诊断 + `deepProfilerQuiet` + `xmlPatchGate` 总闸，共 **78** 个。）
```

## 7. 验证方法说明（下次可复用）

| 步骤 | 命令 / 做法 |
|---|---|
| ① 编号清单 | 从 `About/About.xml` 抓 `【N】`，确认 1–71 连续 |
| ② 开关清单 | 正则从 `源码/FixToggles.cs` 抽 `new Entry("id", GroupXxx, "label")` |
| ③ 一对一核对 | 编号集合 vs 开关 label 里的 `【N】`：缺 / 重 / 越界 |
| ④ 接线对账 | `python 工具/verify-toggles.py`（声明 vs 接线） |
| ⑤ XmlPatch 双向 | `xmlPatchFile:` 登记 vs `Patches/*.xml` |
| ⑥ **动态对照** | 改 `Config/Mod_模组兼容修复补丁_LocalFixesMod.xml` 里对应 `values` 的 True/False，重启看日志 |

**⑥ 的注意事项**：
- 设置文件只存**与默认值不同的**条项（实测 78 个开关里只存了 27 个）
- 键和值是两个平行的 `<li>` 列表，顺序一一对应 —— 改值时要**按索引**改，不能只替换字符串
- 验证完要把 `ModsConfig.xml` 与设置文件都恢复（本轮备份在 `备份/开关动态验证-20261127-160754/`）
