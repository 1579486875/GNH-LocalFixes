### 4b. 订正：幂等性不能用「反复开关模组管理器」验

**本轮发现报告初稿写错了一条判据。** 模板 §4 原文：

> ⚠ **「反复开关游戏内的模组管理器」这条判据在 1.6 与 1.7 上都已失效，别再拿它验幂等。**
> 反编译两份 `Assembly-CSharp`（1.6 / 1.7 结论一致）：`Verse.LoadedModManager.CreateModClasses()`
> 的**唯一调用者**是 `LoadAllActiveMods`，而它只有两个调用者 ——
> `PlayDataLoader.DoPlayLoad` 与 `PlayDataLoader.<>c__DisplayClass6_0.<HotReloadDefs>b__3`。
> **打开游戏内「模组」页面根本不走这条路**，所以连开连关既观察不到叠加，
> 也不会因为「没叠加」而误判通过 —— 它只是**无效**，不是通过。

**改用模板给的两条能落到证据上的判据**：

| # | 判据 | 本轮结果 |
|---|---|---|
| ① **静态**：逐个安装点看有没有一次性守卫 | 见下 | 本轮**补上了一个缺失的** |
| ② **运行时**：看安装日志是否重复 | `已安装 X` 是否出现两次；`installed this pass: N` 是否只出现一次 | 见第 5 节 |

**① 的核查结果（本轮真发现的缺陷）**：

| 安装点 | 守卫 | 结论 |
|---|---|---|
| `BackstoryConstructorTraitsFix.Install()` | `if (installed) return; installed = true;` | ✅ 有 |
| **`LocalFixesMod` 构造函数** | **原先没有** | ❌ **本轮补上 `constructorRan`** |

> 原写法是「构造函数里每一步都 try/catch，尽量不抛」—— **那是降低概率，不是消除**。
> `base(content)` 本身、以及将来有人加的 try 块外代码都可能抛。
> 一旦抛，`runningModClasses` 不写入 → 下次重入 → Harmony 补丁**叠加** → 越操作越卡。
> 已在 `LocalFixesMod.cs` 构造函数体第一行补上静态闸。

## 6. 附录：本轮抓到的两个真缺陷

### 缺陷 1：【70】前四版兜底全部无效

| 版本 | 做法 | 实机结果 |
|---|---|---|
| v1 | 兜 `first`/`second` 为 null | 两个都是 `List(0 项)`，非 null |
| v2 | 直接改 `backstoryTemplate` 字段 | 字段补上了，仍然 NRE |
| v3 | 清洗 `Utility.Traits` | 实机是 `List(505 项)`，不是 null |
| v4 | 加 Finalizer 兜异常 | 兜住了，但那一栏永远画不出来 |

**根因**：崩点在作者 `DrawBackstoryTraits` 内部那段**一处判空都没有**的反解链上
（`TraitDef.Named` → `degreeDatas.Find` → `modContentPack.Name`）。
505 项里只要有一项在当前加载顺序下解析不到，`val4.LabelCap` 直接 NRE。

**修法**：整栏接管，自绘 + 逐项判空。

### 缺陷 2：高度累加与原版不一致

`GenUI.DrawElementStack` 的返回是 `num3 + rowHeight` —— **空列表也返回 25**。
我上一版少算 25（空列表和单行都只加 15），会让「随身物品」整栏错位。

**证据**：`工具/验证布局高度.py` 跑 70 组对照，修后 **0 组不一致**。
