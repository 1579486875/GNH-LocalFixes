# 汉化包 defName 引用误译：按模板全面修正

**日期：2026-11-27**
**委托方**：用户（该汉化包由他接入 DeepSeek API 生成）
**依据模板**：`提示词库\边缘世界本地化翻译提示词.txt`
**目标包**：`Mods\!Translation_AI_Pack`（`! AutoTranslation AI Pack`，作者 `Auto Translator Core`）

---

## 1. 违反了模板的哪一条

模板「禁止修改的内容完整列表 → 标签内部的所有特殊标记」里明确列了：

> **带有下划线_的mod内部标识（defName引用），例如 Luxandra_Inc_WhiteRain、RJW_Cocoon；**

以及总纲：

> 下面列出的所有禁止修改的标记、符号、排版，你必须100%原封不动完整保留，
> 一个字符都不能改、不能删、不能省略

**`hediffName` / `jobDef` 这类字段的值就是 defName 引用** ——
翻成中文后目标 Def 必然查不到。这正是 700 条红字的根因。

**所以：不是「翻错了一个词」，是流水线没有把「defName 引用类字段」列进禁译清单。**

## 3. 第一批：RJW 的 `RacePartDef.hediffName`（65 条）

| 文件 | 污染条数 |
|---|---|
| `DefInjected\rjw.RacePartDef\rim_job_world_AutoTranslated.xml` | **60** |
| `DefInjected\rjw.RacePartDef\castle_tentaclecults_AutoTranslated.xml` | **5** |

### 3.1 改法：按 RJW 本体原值，不是简单替换成 defName

从 RJW 本体 `1.7\Defs\` 下**所有**定义 `RacePartDef` 的文件建映射
（`RacePartDefs.xml` + `CustomRaceParts.xml`，共 **63 个**）：

| 项 | 数量 |
|---|---|
| `defName == hediffName` | **60** |
| **不同** | **2** —— `RJW_CowBreasts → UdderBreasts`、`RJW_SmallHoneyBreasts → Breasts` |
| 没写 `hediffName` | 1（`None`） |

⚠ **关键**：那 2 个不同的**不能按 defName 改**。
`RJW_SmallHoneyBreasts` 的原值是 **`Breasts`**，不是 `RJW_SmallHoneyBreasts`。
（`RJW_CowBreasts` 在汉化包里本来就是 `UdderBreasts`，正确，不动）

### 3.2 结果

```

castle_tentaclecults_AutoTranslated.xml  改  5 /  5 条   XML ✅   中文残留 0
```

`castle_tentaclecults` 那 5 条（`OvipositorTF` 等）对应的模组**未安装**，

## 4. 第二批：扫出来的另外 8 条（`jobDef` 与嵌套 `hediffName`）

| 文件 | 键 | 原值情况 | 处理 |
|---|---|---|---|
| `AbilityDefs\als_gravtech_AutoTranslated.xml` | `GravjumpAbi.jobDef` | 原模组 `als.gravtech` 里 **有**，值 `CastJump` | **改回 `CastJump`** |
| 同上 | `GravShieldAbi.jobDef` | **原模组没有这个字段** | **删除** |
| 同上 | `GravStomachAbi.jobDef` | 无 | **删除** |
| 同上 | `GravShockAbi.jobDef` | 无 | **删除** |
| 同上 | `GravLensAbi.jobDef` | 无 | **删除** |
| 同上 | `GravCapsuleAbi.jobDef` | 无 | **删除** |
| 同上 | `GravRifle_LooongShot.jobDef` | 只有 CE 补丁改 description/range，**没有 jobDef** | **删除** |
| `ThingDef\castle_tentaclecults_AutoTranslated.xml` | `TInternal.comps.1.hediffname` | 模组未装，原值不可知 | **删除** |

### 4.1 怎么判定「原模组有没有这个字段」

原模组 `GravTech`（工坊 `3545374124`，`als.gravtech`）就在工坊目录里，
直接读 `1.7\Defs\Ability_GT.xml`：

```
13 个 AbilityDef，只有 GravjumpAbi 有 jobDef=CastJump，
其余 12 个（GravShieldAbi / GravStomachAbi / GravShockAbi / GravLensAbi / GravCapsuleAbi …）都没有
```

**所以那 6 条 `jobDef` 是 AI 凭空生成的（幻觉）** —— 原模组根本没有这些字段，
游戏解析时会直接忽略，只记进 translation errors。

### 4.2 为什么「删除」而不是「猜一个值」

模板的原则是**不能瞎译**。原值不可知时，**删掉该键 = 回退到原模组的英文值**，
这是唯一安全的选择（留着错的中文反而会让目标 Def 查不到）。

## 7. 给流水线的建议（治本）

这个包覆盖 **617 个 Def 类型目录 / 3,335 个 xml**，靠事后扫只能兜住已知字段。
**真正的修法是在翻译流水线的提示词里加一条硬规则**：

> **凡字段名以 `Def` / `Defs` 结尾，或属于以下清单的，值一律照抄，不得翻译：**
> `defName` `hediffName` `thingDef` `apparelDef` `buildingDef` `weaponDef` `bodyPartDef`
> `damageDef` `soundDef` `effectDef` `ingredientDef` `fixedDef` `texPath` `shaderDef`
> `racePartDef` `filthDef` `needDef` `jobDef` `workGiverDef` `thoughtDef` `recipeUsers`
> `researchPrerequisite` `requiredResearch` `statDef` `capacityDef` `geneDef` `xenotypeDef`
> `memes` `preceptDef` `ritualPatternDef` `abilityDef` `verbClass` `thingClass` `compClass`
> `hediffClass` `workerClass` `driverClass` `relationDef` `interactionDef` `incidentDef`
> `questScriptDef` `rulePackDef`
>
> **另外：`<DefName>.comps.<N>.<field>` 这种嵌套路径同样适用** ——
> 第二批判出的 `TInternal.comps.1.hediffname` 就是嵌套路径漏网。

**更彻底的做法**：翻译前先把目标 mod 的 `Defs\*.xml` 解析成「字段 → 类型」表，
**类型是 Def 子类或 string 但字段名在禁译清单里的，直接跳过不送 AI**。

本仓库的 `工具/扫汉化包defName误译.py` 可以当**事后验收脚本**用 ——
每次流水线跑完扫一遍，非 0 就说明提示词还有漏。
