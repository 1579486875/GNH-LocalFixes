# 【71】到底是谁的问题 —— 责任链清单

**日期：2026-11-27**
**问题**：那 700 条 `Could not find a HediffDef named 肛门…` 是哪个模组造成的？哪里的汉化包搞的？

---

## 一句话答案

**模组侧**：**RimJobWorld**（作者 **Ed86**，`rim.job.world`）——
它把 `RacePartDef.hediffName` 用作 **HediffDef 的 defName 引用**，这是**正常设计**。

**汉化包侧**：**`! AutoTranslation AI Pack`**（作者 **Auto Translator Core**，`AITranslation.Pack`）——
它把这个 **defName 引用当普通文本翻译了**，这是**错误的**。

**RJW 没有 bug，是汉化包翻错了。**

---

## 一、模组侧：RimJobWorld

| 项 | 值 |
|---|---|
| 显示名 | **RimJobWorld** |
| 作者 | **Ed86** |
| packageId | **`rim.job.world`** |
| 本地目录 | `D:\steam\steamapps\common\RimWorld\Mods\RJW_核心_本体\` |
| 相关文件 | `1.7\Defs\RaceSupport\RacePartDefs.xml`（7,033 B，2026-10-21） |
| DLL | `1.7\Assemblies\RJW.dll`（837,120 B，MVID `83b5bb80…`） |

### RJW 这边的写法（完全正常）

```xml
<rjw.RacePartDef>
    <defName>Anus</defName>
    <hediffName>Anus</hediffName>     ← 这就是 HediffDef 的 defName，不是给人看的文本
</rjw.RacePartDef>
```

```csharp
// 反编译 rjw.RacePartDef
public string hediffName;

public bool TryGetHediffDef(out HediffDef hediffDef)
{
    hediffDef = DefDatabase<HediffDef>.GetNamedSilentFail(hediffName);   // ← 拿它当 defName 查
    if (hediffDef == null)
        ModLog.Error("Could not find a HediffDef named " + hediffName
                   + " referenced by RacePartDef named " + base.defName + ".");   // ← 就是那 700 条
    return hediffDef != null;
}
```

**实测**：RJW 本体 `RacePartDefs.xml` 里 **61 个 RacePartDef，60 个 `hediffName` 与 `defName` 完全相同、0 个不同**。

## 二、汉化包侧：`! AutoTranslation AI Pack`

| 项 | 值 |
|---|---|
| 显示名 | **`! AutoTranslation AI Pack`** |
| 作者 | **Auto Translator Core** |
| packageId | **`AITranslation.Pack`** |
| 本地目录 | `D:\steam\steamapps\common\RimWorld\Mods\!Translation_AI_Pack\` |
| **是否工坊订阅** | **不是** —— 工坊目录 `workshop\content\294100\` 里搜不到它，`About\` 下也没有 `PublishedFileId.txt`、没有工坊链接。**是本地安装版。** |
| 规模 | `DefInjected\` 下 **617 个 Def 类型目录**、全包 **7,748 个 xml** |

### 就是这两个文件

```
Mods\!Translation_AI_Pack\Languages\ChineseSimplified\DefInjected\rjw.RacePartDef\
    rim_job_world_AutoTranslated.xml          4,143 B   → 60 条污染
    castle_tentaclecults_AutoTranslated.xml     377 B   →  5 条污染
    asmr_rjw_racesupport_AutoTranslated.xml   5,563 B   →  0 条（这个文件没翻错）
```

**文件名里的 `_AutoTranslated` 后缀就是线索** —— 这个包是**机器自动翻译**生成的中文，
不是人工汉化。

### 污染内容长这样

```xml
<!-- rim_job_world_AutoTranslated.xml -->
<Anus.hediffName>肛门</Anus.hediffName>
<Breasts.hediffName>乳房</Breasts.hediffName>
<Vagina.hediffName>阴道</Vagina.hediffName>
<Penis.hediffName>阴茎</Penis.hediffName>
…

<!-- castle_tentaclecults_AutoTranslated.xml -->
<OvipositorTF.hediffName>大触手帐篷</OvipositorTF.hediffName>
<OvipositorTFS.hediffName>产卵器TFS</OvipositorTFS.hediffName>
…
```

**`hediffName` 是 defName 引用，按本地化规范绝不能译**
（「边缘世界本地化翻译提示词」第 5 条：带下划线的 mod 内部标识、defName 引用必须原样保留）。

## 三、两批污染的实际影响不一样

| 来源文件 | 污染条数 | 对应模组 | 实际会不会刷红字 |
|---|---|---|---|
| `rim_job_world_AutoTranslated.xml` | **60** | **RimJobWorld（已安装）** | **会** —— 就是那 700 条 |
| `castle_tentaclecults_AutoTranslated.xml` | **5** | **`castle.tentaclecults`（未安装）** | **不会** |

**怎么确认的**：

- 把这 5 个 defName（`OvipositorTF` / `OvipositorTFS` / `OvipositorTFSS` / `OvipositorTM` / `UdderTentacle`）
  拿去 RJW 本体的 `RacePartDefs.xml` 里找 → **一个都没有**
- 再全库搜 `Mods\` → **一个都找不到**
- 去修复前的实机日志里数 → **这 5 个各 0 次**

**所以 `castle.tentaclecults` 是一个曾经装过、现在已卸载的模组**，
汉化包里还留着它的翻译残留 —— 不影响运行，只是白躺着。

---

## 四、700 条是怎么来的

修复前的实机日志里，**真正报错的是 20 个不同的 RacePartDef**：

```
Anus / Breasts / CatVagina / CloacalAnus / CloacalPenis / CloacalVagina /
DogPenis / DragonPenis / DragonVagina / FeaturelessChest / MechAnus / MechBreasts /
（还有 8 个，见日志）
```

**20 个 def × 被多个种族各引用一次 ≈ 700 条。**

同一个被污染的 defName（比如 `Anus` → 「肛门」），
只要有一个种族的 `RaceGroupDef` 引用它，那个种族就会在解析时报一次。

---

## 五、我们的修法（不碰任何一方的文件）

**只在内存里改数据**：

```
启动时（[StaticConstructorOnStartup]，Def 数据库填充完之后）
  → 遍历全部 RacePartDef
  → 若 hediffName 查不到对应 HediffDef，且 defName 能查到
  → 把 hediffName 改回 defName
```

**为什么不改汉化包的文件**：
- 那是别人的模组（模板 §0：绝不去改别人模组目录里的东西）
- 对方一更新就被覆盖
- 我们运行时修，**换任何汉化包都管用**

**为什么不改 RJW**：它没写错，改它反而是破坏作者设计。

**实测效果**：`已把 59 个 RacePartDef 的 hediffName 还原成 defName`，
ERROR 总数 **846 → 144**（剩下 144 个全是别的模组的）。

> 为什么是 59 而不是 60：其中有一个 RacePartDef 的 `defName` **也**查不到对应的 HediffDef
> —— 那是 RJW 那个 RacePartDef 本身指向了不存在的 HediffDef，不是译名问题，
> 按「拿不准不动」原则保持原样。

## 六、如果你想从源头解决

三个选项，按推荐度排：

### ① 让汉化包作者修（治本）

要改的就两处：

```
Languages\ChineseSimplified\DefInjected\rjw.RacePartDef\rim_job_world_AutoTranslated.xml
Languages\ChineseSimplified\DefInjected\rjw.RacePartDef\castle_tentaclecults_AutoTranslated.xml
```

**把 `hediffName` 那 65 行从中文改回英文 defName 即可。**
（`rim_job_world` 那 60 条里，60 个 `hediffName` = `defName`，直接照抄键名就行）

同时建议作者把**自动翻译的黑名单**加上 `hediffName` 这类 defName 引用字段 ——
这个包覆盖 617 个 Def 类型，很可能还有别的同类误译没被发现。

### ② 装我们这个补丁（本仓库）—— 已经做了

不用改任何人的文件，启动时自动还原。

### ③ 手动删掉那两个文件（不推荐）

```
Mods\!Translation_AI_Pack\Languages\ChineseSimplified\DefInjected\rjw.RacePartDef\
    rim_job_world_AutoTranslated.xml
    castle_tentaclecults_AutoTranslated.xml
```

删掉后红字也会消失，但**那两个文件里的正常翻译也一起没了**
（不只是 `hediffName`，还有别的字段的正常中文）。
**而且汉化包一更新就回来了。**
