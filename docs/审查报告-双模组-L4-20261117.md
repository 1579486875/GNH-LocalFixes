### D-11 · 三个脚本的 docstring 里有无效转义

| 文件 | 位置 | 症状 |
|---|---|---|

**已修，并做成 `check-py-syntax.py` 闸门 + `tool-health.py` 的「编译告警」检查项。**

### D-12 · `update-template-1818.py` 不认 `--help`，直接写用户的模板文件

它 `open(P, "wb").write(...)` 无条件执行，`P` 指向
`E:\TAML\提示词库\RimWorld模组-全面审查与修复-通用模板.txt`。

本轮我用 `--help` 探测它的用法，结果它**直接跑到了写盘那一步**。万幸插入逻辑是幂等的
（`if "### B.18 四条" not in txt`），写回的字节与原文件**完全一致** ——
事后核对模板 `sha256 = 70cb8a90… / 181,278 B`，与开工会话首次读到的一模一样。

**已加默认 dry-run**：不加 `--write` 只打印「将写入 N 字节（原 M）／是否与原文件逐字节相同」。

### D-13 · README 里三处数字与实现失同步

| 位置 | 原文 | 实际 |
|---|---|---|
| `### 72 个设置项` | 72 | **76** |
| `**72 个开关覆盖全部 66 条修复**` | 72 / 66 | **76 / 69** |
| `（诊断 5 + 崩溃 19 + 刷屏 13 + 兼容 9 + 行为 3 + 剖析 1 + XML 22 = 72）` | 13 / 22 / 72 | **16 / 23 / 76** |
| `代码侧 50 个开关 + XML 补丁 22 个开关` | 50 / 22 | **53 / 23** |

**根因**：README 自己写着「上面这些数字由 `tools/docstats.py` 从源码数出来，不要手改」，
但 `docstats.py` 当时只核了 About 的「现在 N 条」和 README 的另外三处 —— 这五处**从来没被任何闸门管过**。

**修法**：先扩 `docstats.py`（新增「编号体系上限」与三条 README 正则），
让闸门**先报出来**，再按它报的数字改。现在这五处都在自动核对范围内。

### D-15 · 部署目录里躺着 14 个 `.bak-*` 垃圾文件

| 环境 | `Assemblies/` | 文档目录 | 小计 |
|---|---:|---:|---:|
| 1.7 主安装 | 6 | 3 | **9** |
| 1.6 引擎副本 | 2 | 3 | **5** |
| **合计** | **8** | **6** | **14**（约 400 KB） |

文件：`GNH_NMM_Enhanced_ZH.dll.bak-r356` / `.bak-sync`、`NMMOpinionsChineseUI.dll.bak-r348` /
`.bak-r349` / `.bak-r356` / `.bak-sync`、`README.md.bak-sync`、`汉化说明.md.bak-sync`、
`About.xml.bak-r364`、`About.xml.bak-sync`。

**它们不会被游戏加载**（RimWorld 的 `ModContentPack` 只扫 `*.dll`），所以从来没报过错。
但它们是**交付目录里的开发过程垃圾** —— 玩家打开 `Assemblies/` 会以为那是模组文件。

**根因是两条规则叠在一起**：

1. `sync-deploy.py` 把备份写成 `a + '.bak-sync'`，而 `a` 是**部署目录里的目标路径**；
2. `check-deploy-parity.py` 里 `.bak*` 被明确列为**排除项**，而且「多余文件」**不计入失败**
   （原文注释：「删不删都不影响加载」）。

于是备份越积越多，闸门一路绿灯。

**修法**（两边都做了）：

| 动作 | 文件 |
|---|---|
| 备份改落到仓库 `_backup/deploy-sync/<环境>/` | `NMM/tools/sync-deploy.py` |
| 新增 `collect_junk()`，`.bak/.orig/.tmp/.old/.rej` **计入失败** | `NMM/tools/check-deploy-parity.py` |
| 同一套检查加进 `--check` | `GNH/tools/deploy-dll.py` |
| 14 个文件备份到 `_scratch/audit-r44/bak-cleanup/` 后删除 | — |

> ⚠ **第一版 `collect_junk()` 自己也有盲区**：只走了 `DIRS`（`About/` `Assemblies/` …），
> 于是根目录下的 `README.md.bak-sync` / `汉化说明.md.bak-sync` 和
> `About.xml.bak-r364` 这 6 个全被漏掉，是手工扫才发现。已补上根目录文件遍历。
> **闸门自己漏检是最难发现的缺陷** —— 它报「✅ 一致」的时候，你不会再去手工核。

复验：两环境垃圾 **0** ／ 部署一致 **16/16（GNH）· 224/224（NMM）**。

### ③ 两份同名语言目录：**全部一致**

反编译 `Verse.LoadedLanguage`（1.7.5011.24）确认：

```csharp
// .ctor
legacyFolderName = (folderName.Contains("(")
    ? folderName.Substring(0, folderName.IndexOf("(") - 1) : folderName).Trim();

// AllDirectories
dir = <loadFolder>/Languages/<folderName>
if (dir.Exists) { yield return dir; continue; }      // ← 命中就跳过 legacy
dir = <loadFolder>/Languages/<legacyFolderName>
if (dir.Exists) yield return dir;
```

本机 `folderName = "ChineseSimplified (简体中文)"` → **只读带括号那份**，
`Languages/ChineseSimplified` 永远不会被加载。两份必须一致。

实测：主目录 **18 个文件**、`v1.7/Languages` **66 个文件**，逐文件 SHA256 全同。

### ④ 译文引号：424,076 个文本节点，**0 个半角**

GNH 的 2 处半角引号经确认是 **C# / XML 代码片段**（`Scribe_References.Look(ref fixPawn, "fixPawn")`、
`Class="RJW_Menstruation_Fluids.CompProperties_CumGatherer"`），半角在那里是语法的一部分，已进白名单。

### ⑤ 注释覆盖：137 条注释，**0 条纯英文**

18 条「只写 defName」的是分节标注（`<!-- NMM_EnviousOfBreasts -->`），
按本地化提示词第 5 条「带下划线的 mod 内部标识原样保留」属于正确处理，**不改**。

### ⑥ 性能：没有任何补丁挂在「无早退的高频方法」上

| 补丁 | 目标 | 早退 |
|---|---|---|
| `Patch_GenTypes_PreferTelanda` | `GenTypes.GetTypeInAnyAssembly`（极高频） | 两次字符串比较后 `return true` |
