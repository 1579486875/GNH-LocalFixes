## 4. 本局新出现的两条（都不是我们的）

### 4.1 `SpaceTorpedoes` ×3 —— IRBM 的 `MayRequire` 放错了位置

```
16:34:12.678 ERROR Could not resolve cross-reference to Verse.ThingCategoryDef named SpaceTorpedoes (wanter=thingCategories)
```

**根因链**（三步都取证过）：

1. `nekotee.irbmldr`（边缘弹道导弹，工坊 3695591404）的 `LoadFolders.xml` **只有 `<v1.6>`**，
   `supportedVersions` 也只有 1.6 —— 但按 `ModContentPack.InitLoadFolders` 的 fallback 逻辑，
   1.7 下会选中「≤ 当前版本的最高版本」= `v1.6`，**所以 `1.6/` 目录确实被加载了**；
2. 该目录的 `Defs/ItemDef/Item_new.xml` 里有：
   ```xml
   <thingCategories MayRequire="kentington.saveourship2">
       <li>SpaceTorpedoes</li>
   </thingCategories>
   ```
3. **`Config\ModsConfig.xml` 里 `saveourship` 命中 0 次**（SOS2 没装），
   而全库也**没有任何 `ThingCategoryDef named SpaceTorpedoes` 的定义** ——
   说明它本该由 SOS2 提供。

⇒ **`MayRequire` 写在了 `<thingCategories>` 这个嵌套字段元素上，没有生效。**
这是 IRBM 作者的位置问题（`MayRequire` 在嵌套列表字段上不生效），**不是我们的**。

**不改**：改别人的 Def 属于破坏意图；而且这 3 条 ERROR 不影响任何功能
（那 3 个物品只是没有归类）。

### 4.2 `Config error in LDR_ISBM_silo: description has trailing whitespace` ×2

**查过，不是我们的**：

- 我们的 `Patches/SiloTubeIntFieldFix.xml` 只改 `silos/li/size` 与 `coverMovementTicks`，
  **不碰 `description`**；
- 源文件 `3695591404/1.6/Defs/ThingDefs_Buildings/Buildings_MissileSilo_LDR.xml` 里
  `LDR_ISBM_silo` 的 `description` 尾字符是 `'echnologies.'`、**没有空白**。

⇒ 说明是**运行时另有来源改了它**（XML Patch），本轮**未定位**。
影响：只是 `DefDatabase.ErrorCheckAllDefs()` 的一条 Config 警告，**不影响运行**。
