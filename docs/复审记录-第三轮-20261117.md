## 2. 本轮新增的两个静态审计闸门

**为什么必须静态查**：模板 §B.12 明说 `LoadedLanguage.loadErrors`
**从不写进 `Player.log`**。所以下面两类问题在日志里一个字都没有：

| 问题 | 后果 | 原判据为什么不成立 |
|---|---|---|
| 键的 defName 在 def 库里找不到 | 那条译文永不生效 | 只进 `loadErrors` |
| 同一文件里键重复 | 后者覆盖前者 | 同上 |
| 占位符多了/少了 | 显示成 `{XXX}` 或丢信息 | 只在游戏里看到才知道 |

### 2.1 `check-definjected-keys.py`

```
收集：Data +11,727 / Mods +29,125 / workshop +68,298 = 109,150 个 defName
我们的：Languages 两套各 11,283 键 / v1.7 两套各 1,190 键
结果：总键数 24,946 · 悬空 0 · 重复 0
```

**⚠ 第一版踩的坑（记下来）**：只扫了 `Mods` + `workshop`，**漏了原版与 DLC 的 `Data\`**，
于是 `Wait` / `Wait_Combat` / `Wait_MaintainPosture` 三个**原版** JobDef
（`Data\Core\Defs\JobDefs\Jobs_Misc.xml`）被误报成悬空键。
判据必须覆盖**四个来源**：原版 Core、DLC、本地 Mods、工坊。

### 2.2 `check-placeholders.py`

判据分三档（**不是「完全相等」**）：

| 情况 | 判定 | 理由 |
|---|---|---|
| 中文有、英文没有 | **❌** | 那个占位符会原样显示成 `{XXX}` |
| 英文有、中文没有 | **⚠** | 可能是刻意改写，也可能漏了 |
| 多重集相等 | ✅ | — |

结果：对比 **471 键 · ❌ 0 · ⚠ 0**

白名单收了两类确认过的刻意改写：

- **整类**：`…Possessive` 系列 —— v1.4.17 改成 `{…}的`，因为中文语言包没有 LanguageWorker，
  `…Possessive` 会按英文规则渲染成「冯俊晧's」
- **逐键 4 条**：`NMM.Log.{Covering.Default,Covering.Uncaring,Naked.Unable,Naked.Unallowed}.Unaware`
  —— 英文用 `{SELF_objective}self` 拼反身代词，中文没有这种构词法，
  直接写「遮挡身体」是对的，少一个 `{SELF_objective}` 不是丢译

## 3. 本轮验证的四个设计点（都正确，**不是缺陷**）

### 3.1 两条正文通道互斥

反编译 `OwnListInjector..cctor`：

```csharp
if (ran || (!ForceLegacy && HasKeyedPath())) return;   // 有 Keyed 通道就不注入
ran = true; Run();
```

`HasKeyedPath()` 查的是 `NudityMattersMore_opinions.OpinionTextTranslator`：

| 环境 | 那个类型在不在 | 行为 |
|---|---|---|
| 合并版（1.7） | **在**（反编译 `NudityMattersMore.dll` 确认） | 不注入，走 `v1.7/Languages/…/Keyed`（**130,767 键**） |
| 独立版 1.5 / 1.6 | **都不在**（两个 dll 各 67 / 66 类型，都没有） | 注入 `OwnInjections`（47 文件 / **125,750 条**） |

`ForceLegacy` 全程序只有一处**读**、没有写 → 默认 `false` ✓
**所以两条通道不会同时生效，不会互相覆盖。**

### 3.2 `OwnInjections` 的键在三个版本下全部可达

| 目标 | Defs 位置 | defName 数 | 5,214 个键缺几个 |
|---|---|---:|---:|
| 独立版 1.5 | `Common/`（不是 `1.5/`） | 5,350 | **0** |
| 独立版 1.6 | 同上（`1.6/` 只有 Assemblies + Source） | 5,350 | **0** |
| 合并版 1.7 | `1.7/Defs` | 5,567 | **0** |

**这就是「向下兼容旧版本模组」的实质证据** —— 1.5 / 1.6 / 1.7 三套的 defName 都能对上。

### 3.3 整列表注入已经防住「丢末尾几条」

反编译 `OwnListInjector.InjectOneFile`：

```csharp
int num3 = list2.Count - list.Count;     // 原模组条数 - 清单条数
switch (num3) {
    case 1:  // 判继承位置：头条 / 末条 / 判不准
        ...
    default: // 其他任何差值
        skipCount++;
        Log.Warning("条数不符，整条容器跳过以防错位");
        continue;                        // ← 绝不硬覆盖
    case 0: break;                       // 正好相等 → 直接覆盖
}
```

模板 §B.13 说的那个坑（「译文条目少于原文 = 静默丢末尾几条」）**已经被防住**：
条数不符就整条容器跳过 + 打警告，不会写坏数据。

### 3.4 1.7 正文 Keyed 的 19 种占位符全部合法

89,187 次出现，19 种：`PAWN_nameShort`(64,126) / `PAWN_possessive`(8,814) /
`OBSERVER_nameShort`(4,222) / `OBSERVED_nameShort`(2,154) / … / `OBSERVED_gender`(1)

逐个反编译核对 NMM 的 DLL 里有没有对应字面量 —— 连最少的
`{OBSERVED_gender}` / `{OBSERVED_ageBiologicalYears}` / `{OBSERVED_nudityStatus}` /
`{OBSERVED_relationLabel}` 都在。**没有拼写错误。**
